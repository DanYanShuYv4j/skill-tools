# 交互原型 Demo 生成器

## 触发条件与适用场景

- **关键词触发**：用户提到「原型」「demo」「交互原型」「PRD demo」「画原型」「生成demo」「可交互原型」等
- **适用场景**：根据 PRD 生成新功能交互原型、对照前端代码生成模拟 Demo、根据截图/设计稿还原交互效果、在正式开发前快速验证交互逻辑

无论用户是否明确说「原型」二字，只要是在描述一个需要可视化验证的交互流程，都应该考虑使用此 skill。

## 不适用场景

- 用户需要**生产级代码**而非快速原型验证
- 需求**不涉及 UI 交互**（如纯后端 API、数据库迁移）
- 用户已有完整的可运行项目，只需要修 bug 或加功能

## 概述

此 skill 用于生成高保真的前端交互原型 Demo。核心原则：**尽可能与用户提供的截图、PRD 文档和前端源码保持一致**。Demo 不是从零设计，而是对已有设计规范和代码模式的忠实还原。

**范围约束：**
- **仅支持中文**：所有 UI 文案使用中文，不考虑国际化
- **仅桌面端**：不处理移动端响应式适配，固定桌面布局
- **禁止 Emoji 图标**：所有图标使用内联 SVG，严禁使用 emoji 作为图标

## 核心工作流（四阶段）

### 阶段一：信息收集与分析

此阶段的目标是**充分理解需求**，避免后续返工。

#### 1.1 识别输入类型

用户可能提供以下一种或多种输入：

| 输入类型 | 处理方式 |
|---------|---------|
| PRD 文档（.md） | 提取需求明细、用户故事、交互逻辑、状态流转 |
| UI 截图/设计稿 | 参考布局、间距、颜色、组件样式。**有源码时交互逻辑以源码为准，无源码时从截图推断组件类型和交互模式** |
| 前端源码路径 | 读取组件、常量、类型定义，**作为 Demo 组件复用的基准** |
| 口头描述 | 追问细节直到足够清晰 |

#### 1.2 无源码时从截图推断组件交互

当用户只有截图、没有源码可参考时，从截图中识别组件类型并推断交互：

| 截图中的视觉特征 | 推断组件类型 | 交互模式 |
|-----------------|-------------|---------|
| 两列并排列表，选中左列后右列出现选项 | 级联选择器（Cascader） | 第一级→展开第二级→选中关闭 |
| 带搜索框的下拉列表，选项前有勾选框 | 多选搜索下拉（MultiSelect） | 搜索过滤 + 勾选/取消 + 已选 tag |
| 左侧树形结构 + 右侧表格面板 | 树+表格布局（Tree + Table） | 点击树节点→右侧刷新对应数据 |
| 顶部步骤编号 + 连接线 + 内容区 | 步骤导航（Steps） | 上一步/下一步 + 动态步骤数 |
| 顶部 Tab 标签 + 下方内容区 | Tab 切换 | 点击 Tab 切换面板 |
| 模态遮罩 + 居中卡片 | 弹窗（Dialog） | 点击遮罩/取消按钮关闭 |

#### 1.3 追问不清晰的细节

以下情况**必须**向用户确认，不要猜测：
- 截图与 PRD 描述有冲突
- 某交互逻辑（如：点击后跳转还是弹窗？）不明确
- 数据状态（如：空数据、加载中、错误）的展示方式不明确
- 步骤/页面的跳转条件不清楚
- 表单校验规则不完整

### 阶段二：Demo 结构设计

#### 2.1 输出文件结构

固定输出可独立打开的 HTML Demo：

```
demo/
├── index.html     # 入口文件，加载 Vue CDN + demo.js
├── demo.js        # Vue 应用主体（data、computed、methods、template）
├── demo.css       # Demo 样式
└── tokens.css     # 设计令牌（颜色、间距、圆角等 CSS 变量）
```

#### 2.2 确定视图结构

根据 PRD/需求确定需要哪些视图（多视图切换模式）：

| 常见视图 | 说明 |
|---------|------|
| list | 列表页（搜索、表格、分页） |
| create | 创建/编辑页（步骤导航、表单） |
| view | 查看详情页（只读展示） |
| test | 测试/试用页（输入→结果） |

使用 `activeView` 状态变量 + `v-show` 实现视图切换（不引入 vue-router）。

#### 2.3 确定交互状态覆盖（核心）

**每个组件/页面至少覆盖以下五种状态：**

- **正常态**：默认展示
- **空状态**：无数据时的占位提示
- **加载态**：提交/加载中的 spinner 或 disabled
- **错误态**：失败时的错误提示
- **禁用态**：条件不满足时的禁用/占位

**边界场景必须主动追问：** 长时间运行、并发、超时、断网、异常数据等，让产品想清楚这些不是上线后才暴露。

### 阶段三：代码实现

#### 3.1 增量编辑优先

用户反馈后修改 Demo 时，**优先使用增量编辑，避免全文重写**：
- 定位需要修改的具体代码块
- 精确替换
- 只有涉及大量结构性改动时才考虑重写整个文件

#### 3.2 技术栈

- 使用 Vue 3 CDN（`https://unpkg.com/vue@3/dist/vue.global.prod.js`），零依赖，浏览器直接打开
- 复杂场景可用 Vue 3 CDN + Options API
- 样式用 CSS 变量（tokens.css）统一管理

#### 3.3 组件复用策略

**必须：先读源码，再模拟组件行为。** 当用户提供源码时优先使用源码组件；当用户描述的功能与已知系统组件相似时，直接复用系统中的组件模式。

在 Demo 中用原生 HTML + CSS 模拟相同的交互（级联下拉、多选搜索下拉、树组件、步骤条、弹窗等）。

#### 3.4 API Mock 策略

所有数据交互使用 Mock 数据，方法有：
1. **静态数据**：直接在 `data()` 中定义数组/对象
2. **模拟异步加载**：使用 `setTimeout` 模拟 API 延迟
3. **模拟条件过滤**：使用 `computed` 对静态数据做过滤/分页
4. **模拟 CRUD**：在 `methods` 中对数组增删改，配合 toast 反馈

#### 3.5 图标规范：禁止 Emoji，强制 SVG

**绝对禁止使用 emoji 表情符号作为图标。** 所有图标使用内联 SVG（`width="16" height="16" viewBox="0 0 24 24"`，颜色用 `currentColor`）。常用图标包括：搜索、关闭、下拉箭头、编辑、删除、刷新、上传、下载、警告、用户、文件、设置等。

### 阶段四：自检与交付

#### 4.1 自检清单

- [ ] index.html 能正常打开，无 JS 报错
- [ ] 所有视图可正常切换
- [ ] 所有按钮/链接点击有反馈（操作或 toast）
- [ ] **空状态、加载态、错误态、禁用态均有覆盖（五态）**
- [ ] 表单校验逻辑完整（必填项、格式校验）
- [ ] 复杂组件（级联选择器等）的选择→清空→重选流程正确
- [ ] 步骤切换（上一步/下一步）行为正确
- [ ] CSS 变量引用有效（颜色、间距等从 tokens.css 正确加载）
- [ ] 下拉菜单点击外部关闭

#### 4.2 常见遗漏提醒

| 遗漏项 | 检查方式 |
|--------|---------|
| 切换数据源后未清空已选表 | 级联选择器变化时清空下游状态 |
| 表单校验不全 | 对比 PRD 中的必填项和格式要求 |
| 步骤条不随条件变化 | 检查 computed 依赖是否完整 |
| 下拉菜单点击外部不关闭 | 检查全局点击监听 |
| 精细化配置树状态残留 | 切换配置类型时重置树展开/选中状态 |

## 设计原则总结

1. **忠实还原**：Demo 是还原 PRD/截图/源码，不是从零创造
2. **五态覆盖**：每个页面想全正常/空/加载/错误/禁用五种状态，边界上线前暴露
3. **统一风格**：用设计令牌（CSS 变量）保证风格一致
4. **能点能用**：Demo 是能交互的，不是静态图
5. **零依赖**：浏览器直接打开就能看
