# AI Skill 工具箱

两个 AI Skill：**一个负责造，一个负责判**。出自 AI 产品人「产品小祥聊AI」的实际工作流。

## 这是什么

给 Claude 这类 AI 用的"工作说明书"（圈内叫 Skill）。告诉 AI：遇到什么情况、按什么步骤、产出什么东西。

普通人不需要自己会写 Skill——只要会描述自己的工作场景，让 AI 照着造一个；造完用第二个 Skill 打分，不达标就让 AI 改。

```
描述场景 → AI 生成 → 打分 → 修改 → 用起来
```

## 两个工具

| Skill | 作用 | 用法 |
|-------|------|------|
| **skill-builder** | 造 Skill | 用对话引导你描述场景，AI 按官方规范生成一个可直接用的 SKILL.md |
| **skill-quality-evaluator** | 判 Skill | 给一个 Skill 打分（触发30 / 结构25 / 功能25 / 可维护20），指出问题并给修改建议 |

## 快速上手

### 方式一：直接用

把 `skill-builder` 文件夹里的 SKILL.md 内容告诉你的 AI，然后描述你的工作场景：

```
我平时做[工作]，常遇到[场景]，我希望你帮我[要做的事]，产出[格式]。
我不懂怎么写，你直接生成一版给我。
```

AI 会按官方规范帮你生成一个 Skill。

### 方式二：装进 Claude Code

把整个文件夹放进你的 Claude Code 的 `.claude/skills/` 目录，然后在对话里说：

- "帮我创建一个 Skill" → 触发 skill-builder
- "审查一下这个 Skill" → 触发 skill-quality-evaluator

### 方式三：命令行验证（可选）

```bash
python skill-quality-evaluator/scripts/validate_skill.py <你的skill文件夹>
```

## 判断一个 Skill 好不好：4 问

1. **触发** — 需要的时候能被调出来吗？（最重要）
2. **结构** — 规则写得清楚吗？
3. **功能** — 边界情况想到了吗？
4. **可维护** — 以后还能改吗？

收藏不是目的，用上才是。好 Skill 不是收藏来的，是"造出来 + 养出来"的。

## 新增：产品经理系列

### prd-generator（写PRD）

让 AI 帮你写 PRD，且**一步步追问、逼你想闭环**。核心：5 步对话（背景→用户故事→角色权限→功能需求→边界场景）+ 每条需求用 Given/When/Then 写验收条件 + AI 主动列异常清单。开发拿到能直接干活。

```
写PRD → AI 一步步追问 → 你确认 → 生成
```

详见 `prd-generator/SKILL.md`。出自《产品经理的AI技能》系列。
