# Skill 创建引导

以 6 步对话引导用户创建一个清晰、高质量的 Skill。核心原则：**按 Anthropic 官方规范，生成的 SKILL.md 能直接使用**。

## 核心铁律

1. **逐节推进**——每次只问一个步骤，确认后再进入下一步
2. **允许回退**——用户说"回到上一步"或"修改第 X 步"，立即跳转
3. **不确认不生成**——所有步骤走完后，预览确认，用户说"生成"才写文件
4. **对齐官方规范**——name kebab-case、description 含 WHAT+WHEN、正文 < 500 行、无 XML 标签

## 对话流程

### 步骤 1：这个技能做什么

**问**：描述一下你想让 AI 具备什么能力？给一个具体的使用场景。

先帮用户判断这个技能属于哪种类型，不同类型的指令侧重点不同：

| 类型 | 特征 | 指令重点 | 例子 |
|------|------|---------|------|
| 文件/资产生成 | 产出固定格式的文件 | 模板、格式一致性、输出校验 | 生成周报、合同模板、Excel 报表 |
| 工作流自动化 | 多步骤流程 + 校验门禁 | 步骤顺序、每步失败处理、回滚 | 代码审查、数据管道、部署流程 |
| MCP 增强 | 在已有工具之上加编排指引 | 工具调用顺序、错误恢复、降级 | 协调多个飞书 API 完成一个业务操作 |

例如：
> "用户拖入一个 PDF，AI 自动提取表格数据并生成 Excel 汇总" → 工作流自动化
> "用户描述一个数据库查询需求，AI 生成对应的 SQL" → 文件/资产生成

**主动提示**：
- 这个能力现在没有 Skill 的话，AI 做得怎么样？哪里不够好？
- 是一次性任务还是反复使用的流程？
- 输出有没有固定格式要求？

**确认后输出**：
```
## 核心能力
[一句话]

## 典型场景
用户说："...（一句真实的用户原话）"
AI 做：...
产出：...
```

### 步骤 2：什么时候触发

**问**：用户说什么话、或者在什么情况下，这个 Skill 应该生效？

给用户几个选择：

| 触发方式 | 示例 |
|---------|------|
| 关键词 | 用户说"提取表格""PDF 转 Excel" |
| 命令 | 用户输入 `/extract-table` |
| 上下文 | 用户拖入 PDF + 提到"数据""表格" |
| 组合 | 以上多种 |

**主动提示**：
- 反过来想——什么情况**不应该**触发？（比如用户只是看 PDF，不是提取数据）
- 有没有口语化的说法？（"帮我把这个表弄出来"）

**确认后输出**：
```
## 触发规则

应触发：
- "..."
- "..."
- "..."

不应触发：
- "..."
- "..."
```

### 步骤 3：核心工作流

**问**：AI 拿到这个任务后，按什么步骤执行？

引导用户画出步骤：

```
步骤 1: [做什么]           ← 第一步
步骤 2: [做什么]           ← 如果步骤 1 失败怎么办？
步骤 3: [做什么]           ← 产出什么？
```

**主动提示**：
- 每一步失败怎么办？（重试？跳过？告知用户？）
- 有没有外部依赖？（需要某个工具、MCP、文件读写）
- 中间结果需要用户确认吗？还是全自动？
- 有没有分支？（不同输入走不同流程）

**确认后输出**：
```
## 工作流

Step 1: ...
  失败时: ...

Step 2: ...
  失败时: ...

Step 3: ...
  产出: ...
```

### 步骤 4：输出格式

**问**：AI 完成后要产出什么？有没有格式要求？

| 产出类型 | 示例 |
|---------|------|
| 文件 | `.xlsx`、`.md`、`.json` |
| 文本回复 | 一句话总结、结构化报告 |
| 操作 | 创建飞书文档、发送消息 |
| 代码 | SQL、Python、Shell |

**主动提示**：
- 如果产出是文件，有没有模板？
- 需要引用来源吗？（如"每条结论后标注来自 PDF 第几页"）

**确认后输出**：
```
## 输出格式

类型: [文件/文本/操作/代码]
格式: ...
模板: ...
```

### 步骤 5：边界场景

**分 4 类快速过一遍**：

| 类别 | 典型问题 |
|------|---------|
| 输入异常 | 文件格式不对？数据为空？超大文件？ |
| 中途失败 | 某一步失败后，之前的结果要保留还是回滚？ |
| 并发 | 用户快速重复触发怎么办？ |
| 环境 | 依赖的工具不可用怎么办？ |

用户不需要全答——挑最可能发生的 2-3 个确认即可。

### 步骤 6：最终汇总与生成

走完 5 步后，汇总预览：

```markdown
---
name: [kebab-case-name]
description: [WHAT + WHEN + 触发短语]
---

# [技能名称]

## 核心能力
...

## 触发规则
...

## 工作流
...

## 输出格式
...

## 边界处理
...
```

**确认清单**：
- [ ] name 是 kebab-case，与用户确认
- [ ] description 包含 WHAT + WHEN + 触发短语
- [ ] 正文 < 500 行
- [ ] 无 XML 标签
- [ ] 输出路径（默认 `skills/{name}/SKILL.md`）

**用户确认后写文件。**

## 技巧

### 帮用户想没想到的

大部分用户第一次写 Skill，想不到：
- 失败处理——"如果 PDF 是扫描件怎么办？"
- 触发精度——"用户说'表'的时候，是要提取表格还是创建表格？"
- 输出一致性——"每次生成的 Excel 表头是否应该一样？"

主动替用户想到这些问题，用选择题方式呈现。

### 对齐官方规范

生成前对照：
- description 有明确的 WHAT 和 WHEN 吗？
- 有没有口语触发词？（不是只有术语）
- name 符合 kebab-case 吗？
- 指令是可执行的吗？（不是模糊的"帮助用户"）
